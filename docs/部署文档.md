# TradeQuery 部署文档

> 写给买家/使用者的中文部署说明。源码交付后，按本文三步即可跑起来。

---

## 1. 本地运行（推荐先这样验证）

要求：Python 3.10+（3.12 最佳）。

```bash
# 1. 解压源码包，进入目录
cd trade-text2sql

# 2. 创建虚拟环境并安装依赖（首次约 2-5 分钟）
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 3. 配置环境变量
cp .env.example .env
# 用文本编辑器打开 .env，至少填上 LLM_API_KEY（见 3.1）

# 4. 启动（默认 8000 端口）
python -m backend.main
```

浏览器打开 http://localhost:8000：

- `APP_LANG=en`（默认）→ 英文界面；`APP_LANG=zh` → 中文界面
- 点示例问题（或自己提问），能看到回答 + 数据表格 + 可展开的 SQL

## 2. Docker 运行

```bash
# 构建镜像
docker build -t tradequery .

# 运行（SQLite 模式，数据文件保存在具名卷里，重启不丢）
docker run -d --name tradequery -p 8000:8000 \
  -e LLM_API_KEY=你的key \
  -e APP_LANG=zh \
  -v tradequery-data:/app/backend/db \
  tradequery

# 查看日志
docker logs -f tradequery
```

> 说明：镜像启动时会自动建表并灌入演示数据（8 家企业 / 15 信用证 / 20 发运 / 单据 / 8 付款），
> 已有数据的库不会重复灌入。

## 3. `.env` 配置详解

### 3.1 LLM_API_KEY（必填）

去 https://aistudio.google.com/ → Get API key → Create API key（免费），填入即可。
不填也能启动，但提问时会提示未配置 Key。

### 3.2 APP_LANG（界面语言）

| 值 | 效果 |
|---|---|
| `en`（默认） | 英文界面 + 英文问答（外资银行演示用这个） |
| `zh` | 中文界面 + 中文问答（国内交付/闲鱼买家用这个） |

改完重启服务生效。

### 3.3 DATABASE_URL（数据库）

默认 SQLite，零配置。想换 PostgreSQL / MySQL：

```bash
# PostgreSQL（先 CREATE DATABASE tradequery;）
DATABASE_URL=postgresql+psycopg2://用户名:密码@localhost:5432/tradequery

# MySQL（先 CREATE DATABASE tradequery CHARACTER SET utf8mb4;）
DATABASE_URL=mysql+pymysql://用户名:密码@localhost:3306/tradequery
```

- 首次启动会自动建表并灌入演示数据（三种库同一套种子数据）。
- `SQL_DIALECT` 一般不用设，会从 URL 自动推导；三种方言的日期函数已在 SQL 生成 prompt 里做了对照。
- **生产安全要求**：PostgreSQL / MySQL 请用**只授 SELECT 权限**的账号连接
  （`GRANT SELECT ON ALL TABLES IN SCHEMA public TO tradequery_ro;`），
  应用层护栏是第一道，数据库权限是最后一道。

### 3.4 LLM_MODEL（换模型）

默认 `gemini-3.5-flash-lite`（实测最稳定）。备选：

```bash
LLM_MODEL=gemini-3.8-flash
# 或 OpenAI 兼容服务：
# LLM_BASE_URL=https://api.openai.com/v1
# LLM_MODEL=gpt-4o-mini
```

## 4. 常见问题

**Q1：提问报错 `LLM_NOT_CONFIGURED`？**
`.env` 里没填 `LLM_API_KEY`。按 3.1 获取并填入，重启。

**Q2：报错 404 `model ... is no longer available`？**
Google 下架了旧模型。换 `LLM_MODEL=gemini-3.5-flash-lite`（或当时可用的新模型），重启。

**Q3：报错 `Request timed out` / `APITimeoutError`？**
模型服务端拥堵或网络慢。先换 `gemini-3.5-flash-lite` 试试；仍不行可多试几次，
或换网络环境。单次 LLM 调用超时为 60 秒。

**Q4：端口被占用（`address already in use`）？**
改 `.env` 里的 `PORT=8001` 再启动，或关掉占用 8000 的程序。

**Q5：想清空演示数据重新开始？**
删掉 SQLite 文件 `backend/db/trade.db`（默认路径）后重启，会自动重建。
PostgreSQL/MySQL 则删表重建：重启服务会自动建表灌数（空库时）。

**Q6：中文界面下提问，要用中文还是英文？**
用中文。`APP_LANG=zh` 时 Agent 的提示词、示例和回答都是中文的；
`APP_LANG=en` 时用英文提问。

**Q7：如何验证安装成功？**
打开 http://localhost:8000/api/health，应返回 `{"status":"ok",...}`；
再打开 http://localhost:8000/api/schema，应看到 5 张表的结构。

## 5. 目录结构速览

```
trade-text2sql/
├── backend/
│   ├── main.py            # FastAPI：/api/chat /api/schema /api/tables /api/audit + 前端托管
│   ├── agent/
│   │   ├── graph.py       # LangGraph：意图→表关联→SQL生成→护栏→执行→自修复→回答
│   │   ├── guardrail.py   # SQL 安全护栏（只读/白名单/LIMIT/黑名单）
│   │   ├── schema_catalog.py  # 表结构注释 + 中英 few-shot 示例 + 方言日期对照
│   │   └── config.py      # 环境变量：LLM / APP_LANG
│   ├── db/
│   │   ├── db.py          # SQLAlchemy 统一执行层（DATABASE_URL/SQL_DIALECT）
│   │   ├── models.py      # 表定义（SQLite/PG/MySQL 通用）
│   │   └── seed_data.py   # 演示种子数据（8企业/15信用证/20发运/单据/8付款）
│   └── tests/             # pytest（30+ 用例）
├── frontend/
│   ├── index.html         # 英文版（4 Tab）
│   └── index.zh.html      # 中文版（4 Tab）
├── docs/
│   ├── 部署文档.md        # 本文件
│   └── technical-design.md# 技术设计文档
├── Dockerfile / fly.toml  # 容器与 Fly.io 部署
└── .env.example           # 环境变量模板
```
